1. let, const (and var)

Beginner Mental Model

Think of variables as labeled storage boxes in memory. JavaScript gives you three keywords to create these boxes: var (the old 1995 way), let (modern changeable box), and const (modern locked label).

Real-Life Analogy Imagine a hotel room keycard:
  • let is a whiteboard marker on your room door — you can erase the guest name and write a new one.
  • const is an engraved metal nameplate on the door — you cannot swap the nameplate for another door, but the furniture inside that room (object properties / array items) can still be rearranged!
  • var is like shouting across the entire floor — no matter which closet (if/for block) you shouted from, everyone on the whole floor (the entire function) hears it and overwrites each other.

Complete Technical Comparison

Feature var let const
Scope Function-scoped (or Global) Block-scoped { ... } Block-scoped { ... }
Redeclaration in same scope Allowed (silently overwrites!) SyntaxError SyntaxError
Reassignment Allowed Allowed TypeError
Initialize without value? Yes (defaults to undefined) Yes (defaults to undefined) No (SyntaxError: Missing initializer)
Hoisting behavior Hoisted & initialized to undefined Hoisted into TDZ (uninitialized) Hoisted into TDZ (uninitialized)
Attaches to global window? Yes (at top level in browser scripts) No (stored in Script/Declarative Env) No

Deep Dive Cases & Edge Cases

Case 1: The Temporal Dead Zone (TDZ)

The TDZ is the time/region between entering a block scope and the line where a let or const variable is declared and initialized. Accessing the variable inside the TDZ throws a ReferenceError. 

{
  // --- TDZ for 'status' starts here ---
  console.log(status); // ❌ ReferenceError: Cannot access 'status' before initialization
  console.log(typeof status); // ❌ STILL ReferenceError! (Unlike undeclared variables!)
  // --- TDZ ends on the next line ---
  let status = "OPEN";
  console.log(status); // ✅ "OPEN"
}

// Note the weird 'typeof' difference:
console.log(typeof totallyUndeclaredVar); // ✅ "undefined" (safe)
// Inside a TDZ, typeof throws ReferenceError!

Case 2: const Means Constant Binding, NOT Immutable Value

For primitive values (number, string, boolean), const locks the value. For reference types (Object, Array), const only locks the memory address pointer, not the contents inside. 

const ticket = { id: 101, priority: "LOW" };
ticket.priority = "HIGH"; // ✅ Works! Same object reference, property mutated.
// ticket = { id: 102 };  // ❌ TypeError: Assignment to constant variable.

const tags = ["angular", "ts"];
tags.push("rxjs");        // ✅ Works! Array content changed.
// tags = ["react"];      // ❌ TypeError!

// If you want true shallow immutability:
const frozenTicket = Object.freeze({ id: 101, priority: "LOW" });
frozenTicket.priority = "HIGH"; // Fails silently in non-strict mode, TypeError in strict mode!

Case 3: var Leaking Out of if and for Blocks

if (true) {
  var leaked = "I escaped the block!";
  let contained = "I stay inside!";
}
console.log(leaked);    // ✅ "I escaped the block!"
// console.log(contained); // ❌ ReferenceError: contained is not defined
Angular & Full-Stack Production Rule Always default to const. Only switch to let when reassignment is genuinely required (e.g., loop counters, accumulators, retry attempts). Never use var in modern TypeScript/Angular/Node codebases. Also remember: in Angular (OnPush change detection) and React/Redux, mutating a const object/array in place breaks reference equality checks (prev === next), causing UI updates not to trigger!

Interview Questions & Practice Problems

Q1 (Interview): What is the difference between undefined and ReferenceError: x is not defined vs ReferenceError: Cannot access 'x' before initialization?
Show Answer
  • undefined: The variable exists in memory (e.g., hoisted var or declared let a;) and currently holds no assigned value.
  • x is not defined: x was never declared anywhere in the current scope chain.
  • Cannot access 'x' before initialization: x was declared using let/const/class in the current scope, so the engine knows it exists, but you tried to read it while it is still inside its Temporal Dead Zone (TDZ).
Q2 (Predict Output): What will this code log and why?
let x = 10;
function test() {
  console.log(x);
  let x = 20;
}
test();
Show Answer

Output: ReferenceError: Cannot access 'x' before initialization.

Why: Even though outer x = 10 exists, the inner let x = 20 hoists inside test() and creates a local TDZ for x from the top of test() until line let x = 20. The local x shadows the outer x, so JS does not fall back to outer x = 10.

Q3 (Practice Coding): Safely update a user settings object declared with const without mutating the original object, and verify the original remains untouched.
Show Solution 
const defaultSettings = { theme: "light", notifications: true, retries: 3 };

// Wrong (mutates original):
// defaultSettings.theme = "dark";

// Right (creates new reference):
const updatedSettings = {
  ...defaultSettings,
  theme: "dark"
};

console.log(defaultSettings.theme); // "light"
console.log(updatedSettings.theme); // "dark"
console.log(defaultSettings === updatedSettings); // false

2. Scope & Scope Chain (Lexical Scope)

Beginner Mental Model

Scope answers one question: "Where in my code is this variable visible and accessible?"

Real-Life Analogy: One-Way Tinted Glass Building Imagine nested glass rooms: Outer Room (Global) → Middle Room (Function) → Inner Room (Block). If you are standing in the Inner Room, you can look outward through the one-way glass and see variables in the Middle and Outer rooms. However, someone in the Outer Room cannot see inside the Inner Room!

The 4 Types of Scope in JavaScript

  1. Global Scope: Declared outside all functions/blocks. Accessible everywhere. (Avoid polluting it!)
  2. Function (Local) Scope: Created whenever a function is invoked. Parameters and variables inside belong only to that function.
  3. Block Scope: Created by { ... } (if, for, while, standalone blocks) for let, const, and class (and functions in strict mode).
  4. Module Scope: Every ES Module file (.ts / .mjs in Angular, React, Node) has its own private top-level scope. Nothing leaks globally unless explicitly exported.

Lexical Scope & The Scope Chain (How the Engine Resolves Variables)

JavaScript uses Lexical (Static) Scope. This means a function's outer scope is determined by where the function was written in the source code, NOT where it was called from!

When JavaScript looks up a variable:

  1. Check the current Lexical Environment.
  2. If not found, follow the hidden [[OuterEnv]] pointer to the parent Lexical Environment.
  3. Keep walking up the Scope Chain until reaching the Global Environment.
  4. If still not found → throw ReferenceError (or in non-strict mode, accidentally create a global variable if assigning!).
const envName = "GLOBAL";

function outer() {
  const secret = "FROM_OUTER";

  function inner() {
    const local = "FROM_INNER";
    // Scope Chain: inner -> outer -> global
    console.log(local);   // found in inner
    console.log(secret);  // found in outer
    console.log(envName); // found in global
  }

  return inner;
}

function caller() {
  const secret = "FROM_CALLER";
  const fn = outer();
  fn(); // Logs "FROM_OUTER", NOT "FROM_CALLER"! (Lexical scope!)
}

caller();

Variable Shadowing & Illegal Shadowing

Shadowing happens when an inner scope declares a variable with the exact same name as an outer scope variable. The inner variable temporarily "hides" the outer one. 

let role = "VIEWER";

function checkAccess() {
  let role = "ADMIN"; // ✅ Valid shadowing (block/function scope)
  console.log(role);  // "ADMIN"
}
checkAccess();
console.log(role);    // "VIEWER"

// ILLEGAL SHADOWING:
let count = 10;
if (true) {
  // var count = 20; // ❌ SyntaxError: Identifier 'count' has already been declared
  // Why? Because 'var' tries to cross out of the 'if' block into the same scope as 'let count'!
}

// Note: The reverse IS legal:
var mode = "dev";
if (true) {
  let mode = "prod"; // ✅ Legal! 'let' stays confined inside the 'if' block.
}
Interview Trap: Accidental Global Variable In non-strict mode, writing function f() { count = 5; } without let/const/var walks up the scope chain, doesn't find count, and silently creates window.count = 5! In ES Modules, TypeScript, and Angular (which run in "use strict" mode automatically), this throws a ReferenceError.

Interview Questions & Practice Problems

Q1 (Interview): What is the difference between Lexical Scope and Dynamic Scope? Which does JS use?
Show Answer

Lexical Scope binds a function's variable lookup to where the function is physically defined in the code. Dynamic Scope binds it to where the function is called on the runtime call stack. JavaScript uses Lexical Scope for all variables (though the this keyword behaves dynamically depending on the call site!).

Q2 (Predict Output): What gets logged here?
var a = 1;
function first() {
  console.log(a);
}
function second() {
  var a = 2;
  first();
}
second();
Show Answer

Output: 1.

Why: first() was defined in the Global Scope, so its outer lexical reference points to Global, even though it was invoked inside second().

Q3 (Practice): Fix the following function so it neither causes illegal shadowing nor leaks variables globally.
let status = "idle";
function update(flag) {
  if (flag) {
    var status = "loading"; // wait: why does this work or fail?
    serverUrl = "https://api.example.com";
  }
  return status;
}
Show Solution & Explanation

Notice var status = "loading" inside a function actually does NOT fail illegal shadowing because var stops at the function boundary! However, serverUrl has no declaration and leaks globally (or throws in strict mode). Also var status hoists to the top of update(), so if flag is false, update(false) returns undefined instead of "idle"! Fix:

let status = "idle";
function update(flag) {
  const serverUrl = "https://api.example.com";
  if (flag) {
    const localStatus = "loading";
    return { localStatus, serverUrl };
  }
  return { localStatus: status, serverUrl };
}

3. Hoisting & Execution Context

Beginner Mental Model

Many tutorials say "Hoisting moves declarations to the top of the file." Your code doesn't actually move! Instead, the JavaScript engine reads every scope in two phases before running a single line:

  1. Phase 1 — Memory Creation Phase (Compilation/Setup): The engine scans the scope for all declarations (var, let, const, function, class) and reserves memory slots for them.
  2. Phase 2 — Code Execution Phase: The engine runs line by line, assigning values and executing functions.
Real-Life Analogy Think of setting up a theater stage before the play starts:
  • function declaration → The actor is already on stage in full costume before Scene 1 begins (you can call it above its definition!).
  • var → An empty chair labeled with the actor's name and a sticky note saying undefined.
  • let / const / class → A reserved chair wrapped in yellow caution tape (the TDZ). Nobody can sit in it until the exact line in the script where they enter!

All 5 Hoisting Rules Side-by-Side

// 1. Function Declaration -> Fully hoisted (name + body)
greet(); // ✅ "Hello!"
function greet() {
  console.log("Hello!");
}

// 2. var -> Hoisted & initialized to undefined
console.log(port); // ✅ undefined
var port = 3000;

// 3. let / const -> Hoisted, UNINITIALIZED (TDZ -> ReferenceError)
// console.log(apiKey); // ❌ ReferenceError: Cannot access 'apiKey' before initialization
const apiKey = "xyz";

// 4. Function Expression with var -> Variable is undefined, NOT a function!
// sayBye(); // ❌ TypeError: sayBye is not a function
var sayBye = function () {
  console.log("Bye!");
};

// 5. Arrow Function with const -> TDZ ReferenceError if called above
// ping(); // ❌ ReferenceError: Cannot access 'ping' before initialization
const ping = () => console.log("pong");

Advanced Hoisting Edge Cases (Experienced Level)

1. Function vs Variable Precedence

During the Creation Phase, function declarations take priority over var declarations of the same name. However, during Execution, an assignment (=) overwrites it.

console.log(typeof compute); // "function" (function wins during creation!)

var compute = "just a string";
function compute() { return 42; }

console.log(typeof compute); // "string" (execution phase assignment overwrote it!)

2. class Declarations Are Also Hoisted into TDZ

// const svc = new TicketService(); // ❌ ReferenceError: Cannot access 'TicketService' before initialization
class TicketService {}

Interview Questions & Practice Problems

Q1 (Interview): Are let and const hoisted? If yes, why do they throw an error when accessed before declaration?
Show Answer

Yes, they ARE hoisted! The engine allocates memory for them during the Creation Phase. However, unlike var (which is initialized to undefined), let and const remain uninitialized in the Temporal Dead Zone until the execution thread reaches their declaration line. Proof: if let x inside a function wasn't hoisted, accessing x above it would read an outer global x instead of throwing ReferenceError: Cannot access 'x' before initialization!

Q2 (Predict Output — Classic Tricky Question):
var rate = 10;
function calc() {
  console.log(rate);
  if (false) {
    var rate = 50;
  }
  console.log(rate);
}
calc();
Show Answer

Output: undefined, then undefined.

Why: Even though if (false) never runs, var rate is function-scoped and hoisted to the top of calc() during the Creation Phase, shadowing the global rate = 10 with a local rate = undefined.

Q3 (Predict Output): Function Declaration vs Function Expression

Output: First logs 1, then throws TypeError: beta is not a function (because at line 2, beta is undefined, and calling undefined() throws a TypeError).

4. Closures (From First Principles to Production Patterns)

Beginner Mental Model

Normally, when a function finishes running, all its local variables are destroyed and cleared from memory. A closure breaks that rule in a magical way: when an inner function references variables from an outer function and gets returned (or passed to a callback), it packs those outer variables into a "backpack" and carries them around forever!

Real-Life Analogy Imagine a bank account manager (createAccount) who sets up a private vault (balance) and hands you a debit card (an inner function withdraw). Even after the manager goes home (outer function finishes executing), your debit card still remembers and securely accesses that exact private vault! Nobody else can walk into the vault directly.

Technical Definition

A Closure is the combination of a function bundled together with references to its surrounding state (its Lexical Environment). Even after the outer function pops off the Call Stack, its Lexical Environment stays alive on the Heap as long as the inner function holds a reference to it. 

function createCounter(initial = 0) {
  let count = initial; // Private variable stored in closure heap environment

  return {
    increment() {
      count += 1;
      return count;
    },
    decrement() {
      count -= 1;
      return count;
    },
    getValue() {
      return count;
    }
  };
}

const ticketCounter = createCounter(10);
console.log(ticketCounter.increment()); // 11
console.log(ticketCounter.increment()); // 12
console.log(ticketCounter.count);       // undefined! (True data privacy)

5 Real-World Production Use Cases (Why Interviewers Love Closures)

1. Classic Interview Bug: for Loop with var vs let + setTimeout

// BUGGY with var:
for (var i = 1; i <= 3; i++) {
  setTimeout(() => console.log("var:", i), 100);
}
// Logs: var: 4, var: 4, var: 4
// Why? All 3 callbacks share ONE function-scoped 'i', which became 4 before timers ran!

// FIX 1 (Modern): Use 'let' -> creates a fresh lexical binding per loop iteration
for (let j = 1; j <= 3; j++) {
  setTimeout(() => console.log("let:", j), 100);
}
// Logs: let: 1, let: 2, let: 3

// FIX 2 (Pre-ES6 IIFE Closure):
for (var k = 1; k <= 3; k++) {
  ((captured) => {
    setTimeout(() => console.log("IIFE:", captured), 100);
  })(k);
}

2. Debouncing (Crucial for Search Bars in Support Operations Center!)

Prevents firing an API call on every single keystroke; waits until the user pauses typing for delay ms. timerId is remembered across calls via a closure.

function debounce(fn, delay) {
  let timerId; // Persists across keystrokes via closure!
  return function (...args) {
    clearTimeout(timerId);
    timerId = setTimeout(() => {
      fn.apply(this, args);
    }, delay);
  };
}

const searchTickets = debounce((query) => {
  console.log("Fetching tickets for:", query);
}, 300);

3. Memoization (Caching Expensive Calculations)

function memoize(fn) {
  const cache = new Map(); // Protected inside closure
  return function (...args) {
    const key = JSON.stringify(args);
    if (cache.has(key)) return cache.get(key);
    const result = fn.apply(this, args);
    cache.set(key, result);
    return result;
  };
}

5. Stale Closures & Memory Leaks (Senior Awareness)

Production & Angular / React Pitfall
  • Memory Leaks: If an event listener or setInterval or RxJS Observable.subscribe() forms a closure over a huge data array or Angular component instance and you forget to unsubscribe in ngOnDestroy (or takeUntilDestroyed), the Garbage Collector cannot free that memory!
  • Stale Closure: If a callback captures a primitive value (like const count = 0) at render/init time and runs later inside setInterval, it continues reading the outdated 0 forever unless it reads from a mutable reference or latest state setter.

Interview Questions & Practice Problems

Q1 (Interview): Do closures copy variables by value, or keep a live reference to them?
Show Answer

Closures keep a live reference to the variable's Lexical Environment binding, NOT a static snapshot copy! That is why if an outer variable changes after the inner function is created, the inner function sees the updated value (which also explains why the for (var i...) loop prints 4, 4, 4!).

Q2 (Practice Coding): Write a function once(fn) that ensures fn can only be executed one time. Subsequent calls should return the result of the first call without re-running fn.
Show Solution 
function once(fn) {
  let hasRun = false;
  let result;

  return function (...args) {
    if (!hasRun) {
      hasRun = true;
      result = fn.apply(this, args);
    }
    return result;
  };
}

const initDB = once(() => {
  console.log("Connecting to PostgreSQL...");
  return { connected: true };
});

console.log(initDB()); // Logs "Connecting...", returns { connected: true }
console.log(initDB()); // Does NOT log, returns { connected: true }
Q3 (Predict Output):
function createFns() {
  let count = 0;
  function inc() { count++; }
  let msg = `Count is ${count}`;
  function log() { console.log(msg); }
  return [inc, log];
}
const [inc, log] = createFns();
inc();
inc();
log();
Show Answer

Output: "Count is 0"!

Why (Stale Closure Classic!): msg was evaluated ONCE when createFns() ran (when count was 0) and stored as the primitive string "Count is 0". Calling inc() updates count to 2, but never re-evaluates msg!

5. The this Keyword (All 4 Rules + Arrow Functions)

Beginner Mental Model

For regular functions, this does not depend on where the function was written. It depends on HOW the function was called (who is left of the dot at call time!).

Real-Life Analogy The pronoun "I" in English has no fixed person attached to it. If Alice says "I am hungry", "I" = Alice. If Bob says the exact same sentence, "I" = Bob. In JavaScript, this means "whoever is speaking (calling the function) right now."

The 4 Binding Rules (In Order of Precedence: Highest → Lowest)

Rule 1 (Highest): new Binding

Calling a function with new creates a brand new empty object, links its prototype, binds this to that new object, and returns it automatically.

function Ticket(title) {
  this.title = title;
}
const t1 = new Ticket("Login 500 error");
console.log(t1.title); // "Login 500 error"

Rule 2: Explicit Binding (call, apply, bind)

You manually tell JavaScript what this should be.

  • fn.call(obj, arg1, arg2) → Invokes immediately; arguments passed individually (Comma-separated).
  • fn.apply(obj, [arg1, arg2]) → Invokes immediately; arguments passed as an Array.
  • const boundFn = fn.bind(obj, arg1) → Does NOT invoke immediately; returns a permanent new function with this locked to obj (and optional partial arguments).
function introduce(role, city) {
  console.log(`${this.name} is a ${role} in ${city}`);
}
const dev = { name: "Aarav" };

introduce.call(dev, "Angular Dev", "Bengaluru");
introduce.apply(dev, ["Full-Stack Dev", "Pune"]);
const boundIntro = introduce.bind(dev, "AI Engineer");
boundIntro("Hyderabad"); // "Aarav is a AI Engineer in Hyderabad"

Rule 3: Implicit Binding (Left of the Dot)

const agent = {
  name: "Riya",
  greet() {
    console.log("Hi, I am", this.name);
  }
};
agent.greet(); // ✅ Left of the dot is 'agent' -> "Hi, I am Riya"

// TRAP: Lost 'this' when extracting method or passing as callback!
const detached = agent.greet;
detached(); // ❌ Left of dot is NOTHING -> falls back to Default Binding! (undefined or window.name)

Rule 4 (Lowest): Default Binding

  • In "use strict" mode (ES Modules, TypeScript, Angular): standalone fn() sets this to undefined.
  • In non-strict mode: standalone fn() sets this to the global object (window / globalThis).

Arrow Functions & this (The Game Changer)

Arrow functions do NOT have their own this! Instead, they inherit this lexically from the enclosing scope where they were created. Even call, apply, and bind cannot change an arrow function's this! 

const dashboard = {
  serviceName: "SupportOps",
  // Regular method has 'this' = dashboard
  loadTickets() {
    // Arrow function inherits 'this' from loadTickets()!
    setTimeout(() => {
      console.log("Loaded for:", this.serviceName); // ✅ "SupportOps"
    }, 100);
  },
  // DANGER: Arrow function directly as an object method!
  brokenMethod: () => {
    // Enclosing scope is Global/Module, NOT 'dashboard'!
    console.log(this?.serviceName); // ❌ undefined
  }
};
dashboard.loadTickets();
dashboard.brokenMethod();
Angular & DOM Event Listener Connection In a DOM listener btn.addEventListener("click", function() { console.log(this); }), this is the btn DOM element. If you use an arrow function () => console.log(this), this stays bound to your Angular/TS component class instance! That is also why passing a class method like setTimeout(this.onTimeout, 500) loses this unless you write () => this.onTimeout() or define it as an arrow property onTimeout = () => {}.

Interview Questions & Practice Problems

Q1 (Predict Output): What does this log?
const user = {
  name: "Kiran",
  sayHi() { console.log(this.name); },
  sayArrow: () => { console.log(this.name); }
};

Show Answer

  • user.sayArrow() → undefined (Arrow inherits global/module this, where name doesn't exist)

Q2 (Interview Coding): Write a simple polyfill for Function.prototype.myBind.
Show Solution 
Function.prototype.myBind = function (context, ...boundArgs) {
  const originalFn = this; // The function on which .myBind was called
  return function (...callArgs) {
    return originalFn.apply(context, [...boundArgs, ...callArgs]);
  };
};

// Test:
function sum(a, b, c) { return this.base + a + b + c; }
const boundSum = sum.myBind({ base: 100 }, 10);
console.log(boundSum(20, 30)); // 160
Q3 (Interview): Can you change an arrow function's this using .call() or .bind()?
Show Answer

No. Calling arrowFn.call(obj) ignores obj completely (though it still passes the regular arguments). Arrow functions always keep their lexical this captured at creation time.

6. Arrays (Internals, Mutability & Essential Methods)

Beginner Mental Model & Internals

Unlike C++ or Java where arrays are fixed-size contiguous blocks of the same data type, JavaScript arrays are dynamic, resizable, heterogeneous list-like objects (typeof [] === "object"). Always check arrays using Array.isArray(x)!

Under the hood (Experienced edge): Modern JS engines (like V8 in Chrome/Node) optimize dense arrays ([1, 2, 3]) as fast contiguous C-style arrays in memory, whereas leaving gaps (arr[1000] = 5 — a sparse array) forces V8 to fall back to slower hash-table lookups.

Mutating vs. Non-Mutating Methods (Critical for Angular/React!)

Mutating (Modifies Original Array ⚠️) Non-Mutating (Returns New Array / Value ✅)
push(), pop(), shift(), unshift() map(), filter(), reduce(), slice()
splice(), sort(), reverse(), fill() concat(), flat(), flatMap(), [...arr]
Warning: Breaks Angular OnPush & React state diffs! ES2023 Immutable versions: toSorted(), toReversed(), toSpliced(), with()

Core Higher-Order Methods & Traps

const tickets = [
  { id: 1, title: "DB slow", priority: 2, open: true },
  { id: 2, title: "Login crash", priority: 1, open: true },
  { id: 3, title: "Typo in FAQ", priority: 3, open: false }
];

// 1. map -> 1-to-1 transformation (always same length)
const titles = tickets.map(t => t.title);

// 2. filter -> keep items matching predicate
const openTickets = tickets.filter(t => t.open);

// 3. reduce -> collapse array into ANY shape (number, object, grouped map)
const countsByStatus = tickets.reduce((acc, t) => {
  const key = t.open ? "open" : "closed";
  acc[key] = (acc[key] || 0) + 1;
  return acc; // NEVER forget to return acc!
}, {}); // ALWAYS pass initial value ({}) to avoid crashing on empty arrays!

// 4. find / some / every -> SHORT-CIRCUIT (stop early when satisfied!)
const urgent = tickets.find(t => t.priority === 1); // returns first matching object or undefined
const hasOpen = tickets.some(t => t.open);          // boolean
const allOpen = tickets.every(t => t.open);         // boolean

// 5. forEach trap -> Cannot 'break', cannot 'continue' (use return for continue), ignores async/await!
// Use a standard 'for...of' loop if you need 'break' or sequential 'await'.
Top Array Interview Traps

7. Objects (Properties, Cloning, Modern Operators & Prototypes)

Beginner Mental Model

An Object is a collection of key–value pairs (keys are always converted to Strings or Symbols). Primitives (42, "hi", true) are copied by value; Objects (including Arrays & Functions) are copied and compared by memory reference. 

const a = { id: 1 };
const b = { id: 1 };
const c = a;

console.log(a === b); // false (two different objects in heap memory!)
console.log(a === c); // true  (both point to exact same memory address)

Essential Object Inspection & Modern Syntax

const ticket = { id: 42, status: "OPEN", priority: 0, meta: { slaHours: 4 } };

// 1. Iteration APIs
Object.keys(ticket);    // ["id", "status", "priority", "meta"]
Object.values(ticket);  // [42, "OPEN", 0, { slaHours: 4 }]
Object.entries(ticket); // [["id", 42], ["status", "OPEN"], ...]
Object.fromEntries([["a", 1], ["b", 2]]); // { a: 1, b: 2 }

// 2. Destructuring with Rename + Default + Rest
const { status: currentStatus, assignee = "Unassigned", ...rest } = ticket;
// currentStatus = "OPEN", assignee = "Unassigned", rest = { id: 42, priority: 0, meta: ... }

// 3. Optional Chaining (?.) & Nullish Coalescing (??)
const sla = ticket.customer?.tier?.sla ?? 24; // safe if customer/tier is null/undefined

// TRAP: || vs ??
console.log(ticket.priority || 5); // ❌ 5! Because 0 is falsy!
console.log(ticket.priority ?? 5); // ✅ 0! Because ?? ONLY falls back on null or undefined!

Shallow Copy vs. Deep Copy (Huge Interview Topic)

Spread ({ ...obj }) and Object.assign({}, obj) only perform a Shallow Copy — nested objects are STILL shared by reference! 

const original = { name: "Ops", config: { retries: 3 } };
const shallow = { ...original };
shallow.config.retries = 99;
console.log(original.config.retries); // 😱 99! Original nested object got mutated!

// Deep Copy Options:
// 1. structuredClone(obj) -> Modern native standard! Handles Dates, Maps, Sets, circular refs.
//    (Fails only on functions / DOM nodes.)
const deep = structuredClone(original);

// 2. JSON.parse(JSON.stringify(obj)) -> Old hack with major flaws:
//    - Drops undefined values, functions, Symbols
//    - Turns Date objects into ISO strings
//    - Turns NaN / Infinity into null
//    - Crashes on circular references!

Property Descriptors, freeze vs seal & Prototypes

  • Object.freeze(obj): Cannot add, delete, or modify existing properties (shallow!).
  • Object.seal(obj): Cannot add or delete properties, can still modify existing property values.
  • Property Descriptors: Every property has hidden metadata flags: value, writable, enumerable (shows up in Object.keys / for..in), configurable (can delete/redefine).
  • Prototype Chain Basics: Every object has a hidden [[Prototype]] link. When you access obj.toString(), JS checks obj first, then walks up [[Prototype]] to Object.prototype. Use Object.hasOwn(obj, "key") to check only own properties (not inherited ones).
Weird JS Object Keys Trap If you use two different objects as keys on a plain object: const obj = {}; const k1 = {}; const k2 = {}; obj[k1] = "A"; obj[k2] = "B"; → obj[k1] becomes "B"! Why? Both objects convert to the string "[object Object]". Use a new Map() whenever keys are objects or arbitrary types!

Interview Questions & Practice Problems

Q1 (Interview): Difference between ==, ===, and Object.is()?
Show Answer
  • == performs type coercion before comparing (e.g., "5" == 5 is true).
  • === strict equality (no coercion), EXCEPT: NaN === NaN is false, and +0 === -0 is true.
  • Object.is(a, b) behaves like ===, EXCEPT it fixes those two edge cases: Object.is(NaN, NaN) is true, and Object.is(+0, -0) is false. (Used internally by React & Angular Signals!).
Q2 (Practice Coding): Write a custom recursive deepClone(obj) function that handles nested objects, arrays, and primitives.
Show Solution 
function deepClone(value) {
  if (value === null || typeof value !== "object") {
    return value; // Primitives & null
  }
  if (value instanceof Date) return new Date(value.getTime());
  if (Array.isArray(value)) {
    return value.map(item => deepClone(item));
  }
  const cloned = {};
  for (const key of Object.keys(value)) {
    cloned[key] = deepClone(value[key]);
  }
  return cloned;
}

10. Day 1 System Design: How Web Requests Work & Scaling Basics

System Design isn't just for Staff Engineers — product companies test 2+ YoE Frontend & Full-Stack engineers on whether they actually understand what happens between clicking "Submit" in Angular/Next.js and saving a row in PostgreSQL.

Part A: End-to-End Lifecycle of a Request (Your Support Operations Center)

Real-Life Analogy: Ordering Food via Phone
  • DNS Lookup = Looking up the restaurant's phone number in your contacts (Domain name api.supportops.com → IP address 34.120.10.5).
  • TCP + TLS Handshake = Dialing, saying "Hello, can you hear me?" (3-way TCP handshake: SYN → SYN-ACK → ACK), and agreeing on a secret language so nobody eavesdrops (HTTPS/TLS encryption).
  • HTTP Request/Response = Placing your JSON order (POST /api/tickets) and receiving the confirmation receipt (201 Created).

Trace your exact Support Operations Center flow:

  1. Client (Browser — Next.js/Angular): User clicks "Create Ticket". Browser resolves API domain via DNS (cached in Browser → OS → Router → ISP → Root/TLD/Authoritative servers).
  2. Transport Layer (TCP vs UDP):
    • TCP (Transmission Control Protocol): Reliable, ordered, error-checked delivery. Used for HTTP/REST APIs, PostgreSQL connections (you cannot lose half a support ticket!).
    • UDP (User Datagram Protocol): Fast, connectionless, no delivery guarantee. Used for live video/audio calls, gaming, DNS queries, HTTP/3 (QUIC).
  3. Application Layer (HTTP/HTTPS): Next.js sends an HTTPS POST request with JSON payload + JWT in the Authorization header.
  4. Backend (Node.js + Express): Validates request (Zod), verifies JWT, uses Prisma ORM to open a TCP connection to PostgreSQL, inserts row, returns 201 Created.

Part B: Key System Design Metrics & Scaling Basics

  • Latency vs. Throughput:
    • Latency: Time taken for one request to go and come back (e.g., 120 ms). Like how fast one car drives through a tunnel.
    • Throughput: Number of requests handled per second (RPS / QPS, e.g., 5,000 req/s). Like how many cars pass through a 6-lane highway per minute.
  • Vertical Scaling (Scale Up): Upgrade your single Node.js/Postgres server from 4 GB RAM → 64 GB RAM, faster CPU.
    Pros: Zero code changes, simple. Cons: Hardware ceiling, Single Point of Failure (SPOF), downtime during upgrades.
  • Horizontal Scaling (Scale Out): Add more servers (e.g., 5 Node.js Express containers behind a Load Balancer).
    Pros: Nearly limitless scale, fault tolerance (if 1 crashes, 4 survive). Cons: Requires stateless backend (no in-memory sessions — store sessions/tokens in JWT or Redis!), load balancer needed.

Day 1 System Design Interview Questions

Q1: If your Support Operations Center gets 10x traffic tomorrow and you scale Node.js horizontally to 4 instances, what breaks if you stored logged-in users in a local JS Map()?
Show Answer

Users will randomly get logged out! Instance 1 holds their session in its RAM, so when the Load Balancer routes their next request to Instance 2, Instance 2 has no idea who they are. Fix: Keep Node.js stateless using JWTs or an external shared store like Redis.

Q2: Why do we use HTTPS instead of HTTP for internal or external APIs?
Show Answer

HTTP sends headers (including JWTs/passwords) and JSON bodies in plain text over the wire. HTTPS wraps HTTP inside TLS, guaranteeing Confidentiality (encryption), Integrity (tamper detection), and Authentication (SSL certificate proves you are talking to the real server).

11. Day 1 DSA (Sequential): Pattern 1 — Arrays & Hashing (3 Problems)

Pattern Rule of Thumb: Whenever a problem asks "Have I seen this before?", "How many times does X appear?", or "Find a pair that adds to Y", reach for a Set or Map (Hash Table) to trade O(n) space for O(n) speed!

DSA #1: Contains Duplicate (LeetCode #217 — Easy)

Problem: Given an integer array nums, return true if any value appears at least twice, and false if every element is distinct.

  • Brute Force: Nested loop comparing every pair → Time O(n²), Space O(1).
  • Sorting: Sort array and check adjacent neighbors nums[i] === nums[i-1] → Time O(n log n), Space O(1) or O(n).
  • Optimal (Hash Set): Iterate once; if seen.has(num) return true, else seen.add(num). Time O(n), Space O(n).
function containsDuplicate(nums) {
  const seen = new Set();
  for (const num of nums) {
    if (seen.has(num)) return true;
    seen.add(num);
  }
  return false;
}
// Dry run: [1, 2, 3, 1] -> seen:{1} -> {1,2} -> {1,2,3} -> 1 is in seen! -> true

DSA #2: Valid Anagram (LeetCode #242 — Easy)

Problem: Given two strings s and t, return true if t is an anagram of s (same characters with exact same frequencies), and false otherwise.

  • Edge Case First: If s.length !== t.length, immediately return false!
  • Sorting Approach: Sort both strings and compare → Time O(n log n), Space O(n).
  • Optimal (Frequency Map / Array): Count characters of s (+1) and decrement for t (-1). If any count goes below 0, return false. Time O(n), Space O(1) (26 lowercase letters) or O(k) for Unicode.
function isAnagram(s, t) {
  if (s.length !== t.length) return false;

  const freq = new Map();
  for (const ch of s) {
    freq.set(ch, (freq.get(ch) || 0) + 1);
  }
  for (const ch of t) {
    const count = freq.get(ch) || 0;
    if (count === 0) return false;
    freq.set(ch, count - 1);
  }
  return true;
}
// Follow-up Answer: Using a Map naturally supports ALL Unicode characters (emojis, accented letters),
// whereas a fixed new Array(26) only works for lowercase a-z!

DSA #3: Two Sum (LeetCode #1 — Easy)

Problem: Given an array of integers nums and an integer target, return indices of the two numbers such that they add up to target. You may not use the same element twice.

  • Brute Force: Two loops checking nums[i] + nums[j] === target → Time O(n²), Space O(1).
  • Optimal (Single-Pass Hash Map): For each number num at index i, compute complement = target - num. Check if complement is already in our Map (storing value -> index). If yes, return [map.get(complement), i]. Otherwise store map.set(num, i)!
function twoSum(nums, target) {
  const indexByValue = new Map(); // value -> index

  for (let i = 0; i < nums.length; i++) {
    const complement = target - nums[i];
    if (indexByValue.has(complement)) {
      return [indexByValue.get(complement), i];
    }
    indexByValue.set(nums[i], i);
  }
  return [];
}

// Dry run: nums = [3, 3], target = 6
// i=0: num=3, comp=3. Map is {} -> not found. Map becomes {3: 0}.
// i=1: num=3, comp=3. Map has 3 -> returns [0, 1]! (Checking BEFORE inserting avoids reusing index 0!)
// Time: O(n), Space: O(n)
