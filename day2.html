1. Promises (States, Chaining & Combinators)

Beginner Mental Model

JavaScript cannot pause your entire browser tab for 2 seconds while waiting for a backend API response — otherwise the user couldn't scroll or click anything! Before Promises, we used nested callbacks ("Callback Hell"). A Promise is an object representing the eventual completion or failure of an asynchronous operation.

Real-Life Analogy: Coffee Shop Buzzer When you order coffee, the cashier hands you a vibrating buzzer (a Promise).
  • While they brew it, the buzzer is pending (you can go sit down and read your phone — non-blocking!).
  • When your drink is ready, it transitions to fulfilled with a value (your coffee).
  • If the espresso machine broke, it transitions to rejected with a reason (an Error).
  • Once it settles (fulfilled or rejected), it is immutable — a buzzer cannot un-ring or switch from fulfilled to rejected!

Creating, Consuming & Chaining Promises

// 1. Creating a Promise (The executor function runs SYNCHRONOUSLY!)
function fetchTicketById(id) {
  return new Promise((resolve, reject) => {
    if (!id) {
      reject(new Error("Ticket ID is required"));
      return; // Always return after reject/resolve so code below doesn't run!
    }
    setTimeout(() => {
      resolve({ id, title: "PostgreSQL connection pool exhausted", priority: "HIGH" });
    }, 300);
  });
}

// 2. Consuming & Chaining (.then always returns a NEW Promise!)
fetchTicketById(101)
  .then(ticket => {
    console.log("Step 1:", ticket.title);
    return ticket.priority; // Wrapped automatically into a resolved Promise("HIGH")
  })
  .then(priority => {
    console.log("Step 2 Priority:", priority);
  })
  .catch(err => {
    // Catches ANY rejection from ANY step above it!
    console.error("Error caught:", err.message);
  })
  .finally(() => {
    // Runs whether fulfilled OR rejected (ideal for hiding loading spinners!)
    console.log("Cleanup: hide spinner");
  });

The 4 Promise Combinators (Guaranteed Interview Question!)

Method Resolves When... Rejects When... Real-World Use Case
Promise.all([...]) ALL promises fulfill (returns array of values in exact input order) ANY ONE rejects (fail-fast!) Loading Ticket + User + Comments together; page can't render if any fails.
Promise.allSettled([...]) ALL promises settle (never rejects! Returns {status: "fulfilled", value} or {status: "rejected", reason}) Never rejects Sending 10 notification emails or fetching independent dashboard widgets where partial failure is OK.
Promise.race([...]) The FIRST promise settles (if fulfilled) The FIRST promise settles (if rejected!) Implementing an API request timeout by racing fetch() against a 5s timer!
Promise.any([...]) The FIRST promise fulfills (ignores earlier rejections!) ALL reject (throws AggregateError) Fetching an asset from 3 CDN mirrors — take whichever succeeds first! 
// Classic Interview Pattern: Implementing a Timeout with Promise.race()
function withTimeout(promise, ms) {
  const timeout = new Promise((_, reject) =>
    setTimeout(() => reject(new Error(`Timed out after ${ms}ms`)), ms)
  );
  return Promise.race([promise, timeout]);
}
Angular & RxJS Bridge (Your 2 YoE Edge!) Interviewers love asking: "Promise vs RxJS Observable?"
  • Execution: Promises are eager (the executor runs immediately when created); Observables are lazy (nothing runs until .subscribe()).
  • Values: Promises emit a single value; Observables emit 0, 1, or many values over time (streams).
  • Cancellation: Promises have no built-in cancellation (must use AbortController for fetch); Observables are natively cancellable via subscription.unsubscribe() or switchMap.
  • Conversion: In modern Angular, convert a single-emission Observable to a Promise using firstValueFrom(obs$) or lastValueFrom(obs$) (replacing deprecated .toPromise()).

Q2 (Interview Coding): Write your own polyfill for Promise.all(promises).
Show Solution 
function myPromiseAll(iterable) {
  const items = Array.from(iterable);
  return new Promise((resolve, reject) => {
    if (items.length === 0) return resolve([]);
    const results = new Array(items.length);
    let completed = 0;

    items.forEach((item, index) => {
      // Wrap in Promise.resolve in case an item is a plain primitive like 42!
      Promise.resolve(item)
        .then(value => {
          results[index] = value; // Preserve input order, NOT completion order!
          completed++;
          if (completed === items.length) resolve(results);
        })
        .catch(reject); // Fail fast on first rejection
    });
  });
}

2. async / await Mastery

Beginner Mental Model

async/await is syntactic sugar built on top of Promises (and Generators under the hood). It lets you write asynchronous code that looks clean and top-to-bottom like synchronous code, without actually blocking the main thread!

  • Adding async before a function guarantees it always returns a Promise. If you return 42, JS wraps it as Promise.resolve(42). If you throw an error, it returns a rejected Promise.
  • await pauses execution of only that async function until the awaited Promise settles, freeing the Call Stack to handle clicks, animations, and other requests.

4 Huge Production Traps with async/await

Trap 1: Accidental Sequential Waterfall (Slow Performance!)

// ❌ SLOW (Takes 1s + 1s = 2 seconds!)
async function loadDashboardSlow(userId) {
  const user = await fetchUser(userId);      // waits 1s
  const tickets = await fetchTickets(userId); // didn't even start until user finished!
  return { user, tickets };
}

// ✅ FAST (Takes max(1s, 1s) = 1 second!)
async function loadDashboardFast(userId) {
  const [user, tickets] = await Promise.all([
    fetchUser(userId),
    fetchTickets(userId)
  ]);
  return { user, tickets };
}

Trap 2: forEach Does NOT Wait for await!

// ❌ BROKEN: Logs "All done!" BEFORE any ticket is saved!
async function saveAllBroken(ids) {
  ids.forEach(async (id) => {
    await saveTicket(id); // forEach ignores the returned Promise!
  });
  console.log("All done!");
}

// ✅ FIX A (Sequential — when order or rate-limit matters):
async function saveSequential(ids) {
  for (const id of ids) {
    await saveTicket(id);
  }
  console.log("All done sequentially!");
}

// ✅ FIX B (Parallel — fastest!):
async function saveParallel(ids) {
  await Promise.all(ids.map(id => saveTicket(id)));
  console.log("All done in parallel!");
}

Trap 3: Missing await on return inside try / catch!

async function failingQuery() {
  throw new Error("PostgreSQL syntax error");
}

// ❌ BUG: try/catch NEVER catches the error if you omit 'await' before return!
async function brokenWrapper() {
  try {
    return failingQuery(); // Returns the pending/rejected Promise directly, leaving try/catch immediately!
  } catch (err) {
    console.log("Caught?", err.message); // NEVER RUNS!
  }
}

// ✅ FIX: Always use 'return await' inside a try/catch block!
async function fixedWrapper() {
  try {
    return await failingQuery();
  } catch (err) {
    console.log("Caught!", err.message); // ✅ Runs!
    return null;
  }
}

Trap 4: Express Async Error Trap (Your Support Operations Center Backend!)

Node / Express v4 Critical Pitfall In Express 4, if an async route handler throws an error without try { ... } catch (err) { next(err); }, Express does NOT automatically catch the rejected Promise — the request hangs forever or crashes Node with UnhandledPromiseRejection! (Express 5 fixes this natively, or in Express 4 wrap async controllers in a helper or try/catch + next(err)).

3. The Event Loop (Call Stack, Microtasks & Macrotasks)

Beginner Mental Model

JavaScript is single-threaded — it has only one Call Stack and can execute only one line of JS at a time. Yet browsers and Node.js handle timers, network calls, and mouse clicks concurrently! How? Because the Browser / Node Runtime provides multi-threaded background helpers (Web APIs / libuv), and the Event Loop coordinates when finished callbacks re-enter the Call Stack.

Real-Life Analogy: One Chef + Two Ticket Lines
  • Call Stack = The single Chef cooking one dish at a time.
  • Web APIs (Timers / Fetch) = Smart ovens and delivery drivers running in the background while the Chef keeps cooking.
  • Microtask Queue (VIP Line) = Urgent Promise continuations (.then, await, queueMicrotask). The Chef must clear EVERY SINGLE VIP order (even newly added ones!) before taking even one order from the regular line!
  • Macrotask / Callback Queue (Regular Line) = setTimeout, setInterval, DOM click events. The Chef processes ONE regular order per loop turn, then checks if the browser needs to repaint the screen, then drains the VIP line again!
┌───────────────────┐ ┌─────────────────────────────────┐ │ CALL STACK │─────▶│ Web APIs / Node libuv │ │ (Sync JS executes │ │ (fetch, setTimeout, DOM, fs) │ │ line by line) │ └───────────┬─────────────────────┘ └─────────▲─────────┘ │ completes & queues callback │ ▼ │ ┌─────────────────────────────────────────┐ │ │ 1. MICROTASK QUEUE (VIP - Drain ALL!) │ │ │ Promise.then/catch/finally, await, │ │ │ queueMicrotask, MutationObserver │ │ └───────────────────┬─────────────────────┘ │ │ empty? then pick ONE from: │ ┌───────────────────▼─────────────────────┐ └────────│ 2. MACROTASK QUEUE (1 Task per Tick) │ Event Loop │ setTimeout, setInterval, I/O, UI │ └─────────────────────────────────────────┘

Exact Execution Order Rule

  1. Run all Synchronous code on the Call Stack until empty.
  2. Drain the entire Microtask Queue (if a microtask queues another microtask, run that too before moving on!).
  3. (Browser) Perform UI Render / Paint / requestAnimationFrame if needed (~60fps).
  4. Pop ONE task from the Macrotask Queue, run it on the Call Stack.
  5. Go back to Step 2 (Drain all Microtasks again)!
Microtask Starvation & Node.js Difference
  • Microtask Starvation: Calling function loop() { Promise.resolve().then(loop); } freezes the browser UI completely! Macrotasks (clicks, timers) and UI repaints never get a turn because the Microtask Queue never empties.
  • Node.js Extra Detail: In Node.js, process.nextTick() runs in a special queue even before regular Promise Microtasks! And setImmediate() runs in the Check phase of Node's libuv event loop (often before setTimeout(0) inside an I/O callback).

4. map / filter / reduce (Pipelines & Polyfills)

Why Today Focuses Deeper on Functional Pipelines

Yesterday we covered mutating vs non-mutating Array basics. Today, we go to the interview-winning level: writing custom polyfills (frequently asked in JS coding rounds!), chaining pipelines cleanly, and mastering reduce as the universal Swiss Army Knife.

Callback Signature (All Three Share This!)

  • arr.map((element, index, array) => newValue, thisArg) → Returns new array of exact same length.
  • arr.filter((element, index, array) => boolean, thisArg) → Returns new array containing elements where callback returned truthy.
  • arr.reduce((accumulator, element, index, array) => nextAcc, initialValue) → Collapses array into a single output value.

Writing Production-Clean Polyfills (Must-Know!)

// 1. Array.prototype.myMap
Array.prototype.myMap = function (callback, thisArg) {
  const result = [];
  for (let i = 0; i < this.length; i++) {
    if (i in this) { // Respects sparse arrays just like the native spec!
      result[i] = callback.call(thisArg, this[i], i, this);
    }
  }
  return result;
};

// 2. Array.prototype.myFilter
Array.prototype.myFilter = function (callback, thisArg) {
  const result = [];
  for (let i = 0; i < this.length; i++) {
    if (i in this && callback.call(thisArg, this[i], i, this)) {
      result.push(this[i]);
    }
  }
  return result;
};

// 3. Array.prototype.myReduce (Handles missing initialValue properly!)
Array.prototype.myReduce = function (callback, initialValue) {
  const hasInitial = arguments.length >= 2;
  if (!hasInitial && this.length === 0) {
    throw new TypeError("Reduce of empty array with no initial value");
  }
  let acc = hasInitial ? initialValue : this[0];
  let startIndex = hasInitial ? 0 : 1;

  for (let i = startIndex; i < this.length; i++) {
    if (i in this) {
      acc = callback(acc, this[i], i, this);
    }
  }
  return acc;
};

Real-World Support Operations Center Pipeline

const incidents = [
  { id: "INC-1", team: "auth", severity: "P1", minsOpen: 45, resolved: true },
  { id: "INC-2", team: "db",   severity: "P1", minsOpen: 120, resolved: false },
  { id: "INC-3", team: "auth", severity: "P2", minsOpen: 30, resolved: true },
  { id: "INC-4", team: "db",   severity: "P1", minsOpen: 80, resolved: true }
];

// Single-pass reduce (avoids creating intermediate arrays from .filter().map() on large datasets!)
const p1ResolvedStats = incidents.reduce(
  (acc, inc) => {
    if (inc.severity === "P1" && inc.resolved) {
      acc.count += 1;
      acc.totalMins += inc.minsOpen;
      acc.ids.push(inc.id);
    }
    return acc;
  },
  { count: 0, totalMins: 0, ids: [] }
);
console.log(p1ResolvedStats); // { count: 2, totalMins: 125, ids: ["INC-1", "INC-4"] }
Classic JS Quiz Trap: ["1", "2", "3"].map(parseInt) Output is [1, NaN, NaN]! Why? Because map passes 3 arguments (val, index, arr) to parseInt(str, radix):
  • parseInt("1", 0) → radix 0 defaults to base 10 → 1
  • parseInt("2", 1) → base 1 doesn't exist → NaN
  • parseInt("3", 2) → "3" isn't valid in binary (base 2) → NaN!
Fix: ["1", "2", "3"].map(s => parseInt(s, 10)) or .map(Number).

5. Destructuring (Arrays, Objects, Nested & Function Params)

Beginner Mental Model

Destructuring lets you unpack values from arrays or properties from objects directly into distinct variables in a single, readable line. Think of it as pattern matching on the left-hand side of =.

Every Pattern & Edge Case You Need

// 1. Array Destructuring (Position-based!)
const coords = [12.97, 77.59, 920];
const [lat, lng] = coords;          // lat=12.97, lng=77.59
const [, , altitude] = coords;      // Skip elements with commas!
const [head, ...tail] = [1, 2, 3];  // head=1, tail=[2, 3]

// Classic Variable Swap without a temp variable:
let a = 10, b = 20;
[a, b] = [b, a]; // a=20, b=10

// 2. Object Destructuring (Key-name-based!)
const ticket = {
  id: 500,
  title: "502 Bad Gateway",
  assignee: null,
  meta: { region: "ap-south-1" }
};

// Rename + Default value + Nested extraction:
const {
  id: ticketId,
  status = "OPEN",                    // undefined -> uses default "OPEN"
  assignee = "Unassigned",            // ⚠️ CAREFUL! assignee is null, NOT undefined! So assignee stays null!
  meta: { region: awsRegion } = {}    // Default {} prevents TypeError if meta is missing!
} = ticket;

console.log(ticketId, status, assignee, awsRegion); // 500, "OPEN", null, "ap-south-1"

// 3. Computed Property Destructuring
const dynamicField = "title";
const { [dynamicField]: heading } = ticket; // heading = "502 Bad Gateway"

// 4. Function Parameter Destructuring (Express / React / Angular options!)
function createAlert({ channel = "slack", severity = "warn", message } = {}) {
  console.log(`[${channel}] (${severity}): ${message}`);
}
createAlert({ message: "High CPU" }); // Works!
createAlert();                        // Works too because of trailing '= {}'!
2 Subtle Destructuring Traps
  1. Defaults ONLY trigger on strict undefined — never on null, 0, "", or false!
  2. Destructuring null or undefined throws TypeError: const { a } = null; crashes! Always guard API responses with const { a } = response ?? {};.

6. Spread & Rest Operators (...)

Beginner Mental Model

Both operators look identical (...), but their job depends on where they are placed:

  • REST = Collect / Pack remaining items INTO a single Array or Object. Used in function parameters or on the left side of destructuring. (Must always be the last item!)
  • SPREAD = Expand / Unpack an Array, String, Set, or Object OUT into individual elements/properties. Used in function calls or array/object literals.
// 1. REST in Function Parameters (Replaces legacy 'arguments'!)
// Why better than 'arguments'?
// - 'args' is a REAL Array (has .map/.reduce), whereas 'arguments' is array-like.
// - Arrow functions do NOT even have their own 'arguments' object!
function logAudit(actor, ...actions) {
  console.log(`${actor} performed:`, actions.join(", "));
}
logAudit("Admin", "LOGIN", "UPDATE_SLA", "CLOSE_TICKET");

// 2. REST in Object Destructuring (Omit sensitive fields cleanly!)
const dbUser = { id: 1, email: "a@b.com", passwordHash: "$2b$10$..." };
const { passwordHash, ...safeUser } = dbUser; // safeUser = { id: 1, email: "a@b.com" }

// 3. SPREAD in Arrays, Strings, Sets & Function Calls
const nums = [10, 45, 22];
console.log(Math.max(...nums));           // 45 (unpacks into Math.max(10, 45, 22))
const unique = [...new Set([1, 2, 2, 3])]; // [1, 2, 3]
const chars = [..."OPS"];                  // ["O", "P", "S"]

// 4. SPREAD in Objects (Order matters! Later keys overwrite earlier keys)
const defaults = { timeout: 3000, retries: 2 };
const prodConfig = { ...defaults, retries: 5 }; // { timeout: 3000, retries: 5 }

// 5. Conditional Property Spreading (Super clean React/Angular/Node pattern!)
const isAdmin = true;
const payload = {
  userId: 9,
  ...(isAdmin && { role: "SUPER_ADMIN" }) // If false, spreading 'false' adds nothing!
};
Warning: Spread on Objects vs Arrays Spreading an object inside an array ([...{ a: 1 }]) throws a TypeError: object is not iterable! However, spreading an array inside an object ({ ...["x", "y"] }) works and produces { "0": "x", "1": "y" }. And remember from Day 1: spread only creates a shallow copy!

Task 3 (Write): Build retryAsync(fn, retries, delayMs) that retries a failing async function up to retries times with a pause between attempts.
Show Solution 
const sleep = (ms) => new Promise(res => setTimeout(res, ms));

async function retryAsync(fn, retries = 3, delayMs = 300) {
  let lastError;
  for (let attempt = 1; attempt <= retries; attempt++) {
    try {
      return await fn();
    } catch (err) {
      lastError = err;
      console.warn(`Attempt ${attempt} failed: ${err.message}`);
      if (attempt < retries) await sleep(delayMs);
    }
  }
  throw lastError;
}
Task 4 (Write): Build a createConcurrencyQueue or batch runner that processes 10 ticket IDs in batches of 3 at a time using Promise.allSettled.
Show Solution 
async function processInBatches(items, batchSize, workerFn) {
  const results = [];
  for (let i = 0; i < items.length; i += batchSize) {
    const batch = items.slice(i, i + batchSize);
    const settled = await Promise.allSettled(batch.map(workerFn));
    results.push(...settled);
  }
  return results;
}

9. Day 2 System Design: API Styles, Caching & Rate Limiting

Part A: Choosing the Right Communication Protocol

Protocol How It Works When to Use in Support Operations Center
REST (HTTP/JSON) Stateless request/response over HTTP verbs (GET, POST, PATCH, DELETE). Default choice for CRUD endpoints: GET /tickets, POST /tickets. Easy caching, great tooling.
GraphQL Single endpoint; client asks for exact fields needed (solves over/under-fetching). Complex dashboards fetching deeply nested User + Team + Tickets + Comments in one query.
SSE (Server-Sent Events) Unidirectional Server → Client stream over plain HTTP. Streaming AI responses token-by-token (like ChatGPT!) or one-way live ticket feed!
WebSockets Full-duplex (two-way) persistent TCP connection. Real-time agent-customer live chat or collaborative ticket editing ("Agent B is typing...").

Part B: Caching (Why & How — Redis Cache-Aside Pattern)

Reading PostgreSQL on disk takes ~5–50 ms; reading RAM in Redis takes <1 ms. For high-read endpoints like "Dashboard Open Ticket Counts" or "User Permissions", use the Cache-Aside (Lazy Loading) pattern:

  1. Express receives GET /api/stats → checks Redis first.
  2. Cache Hit: Data exists in Redis → return immediately in 1 ms!
  3. Cache Miss: Query PostgreSQL → write result to Redis with a TTL (Time-To-Live, e.g., 60s) → return to client.
  4. Cache Invalidation: When a new ticket is created/closed, either delete the cache key (redis.del("stats")) or let the short TTL expire.

Part C: Rate Limiting (Protecting Your Express + AI APIs!)

If a buggy frontend loop or attacker hits your AI Ticket Summarization endpoint 1,000 times/sec, your OpenAI/LLM bill explodes and PostgreSQL crashes! Place a Rate Limiter middleware (e.g., backed by Redis) at the API Gateway / Express layer:

  • Token Bucket Algorithm: User gets a bucket of e.g. 20 tokens refilling at 2 tokens/sec. Allows short bursts cleanly while capping sustained abuse.
  • Sliding Window Log/Counter: Strictly allows max 100 requests in any rolling 60-second window. Return HTTP 429 Too Many Requests with a Retry-After header!

DSA #4: Group Anagrams (LeetCode #49 — Medium)

Problem: Given an array of strings strs, group the anagrams together. You can return the answer in any order.
Example: ["eat","tea","tan","ate","nat","bat"] → [["bat"],["nat","tan"],["eat","tea","ate"]]

  • Approach 1 (Sort Key): Sort each word's letters ("eat" → "aet") and use it as a Hash Map key. Time: O(n · k log k) where k = max word length.
  • Approach 2 (Optimal Frequency Signature): Count the 26 lowercase letters for each word into an array [1,0,0,0,1,...,1...] and join with a delimiter "#" as the Map key! Time: O(n · k), Space: O(n · k).
function groupAnagrams(strs) {
  const groups = new Map();

  for (const word of strs) {
    const counts = new Array(26).fill(0);
    for (let i = 0; i < word.length; i++) {
      counts[word.charCodeAt(i) - 97]++; // 'a' is ASCII 97
    }
    const signature = counts.join("#"); // Delimiter prevents [1, 10] colliding with [11, 0]!
    if (!groups.has(signature)) groups.set(signature, []);
    groups.get(signature).push(word);
  }

  return Array.from(groups.values());
}
// Edge case: [""] -> signature "0#0#...#0" -> [[""]]

DSA #5: Top K Frequent Elements (LeetCode #347 — Medium)

Problem: Given an integer array nums and an integer k, return the k most frequent elements. Your algorithm's time complexity must be better than O(n log n)!

  • Sorting Frequencies: Count frequencies in Map, sort entries by count → O(n log n) (too slow for the follow-up!).
  • Optimal (Bucket Sort in O(n) Time!): 1. Build a frequency Map (num → count).
    2. Notice the maximum possible frequency of any number is nums.length! Create an array of buckets of size nums.length + 1, where buckets[freq] holds all numbers appearing freq times.
    3. Walk backwards from the highest bucket nums.length down to 1, collecting elements until we have k items!
function topKFrequent(nums, k) {
  const freq = new Map();
  for (const n of nums) {
    freq.set(n, (freq.get(n) || 0) + 1);
  }

  // buckets[i] stores array of numbers that appear exactly i times
  const buckets = Array.from({ length: nums.length + 1 }, () => []);
  for (const [num, count] of freq.entries()) {
    buckets[count].push(num);
  }

  const result = [];
  for (let count = buckets.length - 1; count >= 1 && result.length < k; count--) {
    for (const num of buckets[count]) {
      result.push(num);
      if (result.length === k) return result;
    }
  }
  return result;
}
// Dry run: nums = [1,1,1,2,2,3], k = 2
// freq = {1:3, 2:2, 3:1} -> buckets[3]=[1], buckets[2]=[2], buckets[1]=[3]
// Walk backwards -> pushes 1, then 2 -> returns [1, 2]!
// Time: O(n), Space: O(n)

DSA #6: Product of Array Except Self (LeetCode #238 — Medium)

Problem: Given an integer array nums, return an array answer such that answer[i] equals the product of all elements of nums except nums[i]. Must run in O(n) time and without using the division operator!

  • Why no division? Division breaks if there is a 0 in the array (divide-by-zero!).
  • Core Intuition (Prefix × Suffix): For any index i, the product of everything except nums[i] is simply:
    (Product of everything to the LEFT of i) × (Product of everything to the RIGHT of i)!
  • Optimal O(1) Extra Space:
    Pass 1 (Left → Right): Store prefix products directly inside answer[i].
    Pass 2 (Right → Left): Maintain a running suffix variable and multiply it into answer[i]!
function productExceptSelf(nums) {
  const n = nums.length;
  const answer = new Array(n).fill(1);

  // Pass 1: answer[i] gets product of all elements to the LEFT of i
  let prefix = 1;
  for (let i = 0; i < n; i++) {
    answer[i] = prefix;
    prefix *= nums[i];
  }

  // Pass 2: Multiply by product of all elements to the RIGHT of i
  let suffix = 1;
  for (let i = n - 1; i >= 0; i--) {
    answer[i] *= suffix;
    suffix *= nums[i];
  }

  return answer;
}

// Dry run: nums = [1, 2, 3, 4]
// After Pass 1 (prefixes): answer = [1, 1, 2, 6]
// Pass 2 (suffixes from right):
//   i=3: ans[3]=6*1=6,  suffix=1*4=4
//   i=2: ans[2]=2*4=8,  suffix=4*3=12
//   i=1: ans[1]=1*12=12, suffix=12*2=24
//   i=0: ans[0]=1*24=24, suffix=24*1=24
// Output: [24, 12, 8, 6]! Handles zeros natively (e.g. [-1, 1, 0, -3, 3] -> [0, 0, 9, 0, 0])!
// Time: O(n), Extra Space: O(1) (excluding output array)
